# 阅读站的构建与维护

在线地址：[TechCodex 阅读站](https://liuxd-1230.github.io/TechCodex/)。部署是否已经完成，以最终验收记录和实际 HTTP 访问为准。

## 单一正文来源

正文保存在仓库的 `模拟/`，在 GitHub 可以直接读。网站使用 MkDocs 1.6.1、Material 9.7.7；构建脚本把同一批文件复制到忽略的 `build/book-source/`，按稳定英文网址重写相对链接，然后构建 `site/`。不维护两份独立教材。

网站专用样式与模板在 `web/`。构建时的 figure/figcaption 转换只增强语义，不要求正文采用专用短代码。普通 Markdown、LaTeX 和原生 details 在 GitHub 仍可读。

```powershell
python -m venv .venv-site
.\.venv-site\Scripts\python.exe -m pip install -r requirements-site.txt
.\.venv-site\Scripts\python.exe scripts/book.py build
.\.venv-site\Scripts\python.exe scripts/check_site.py
.\.venv-site\Scripts\python.exe scripts/book.py serve
```

`build` 使用严格模式。`serve` 默认监听 `127.0.0.1:8000`，不向局域网公开；源文件修改后重启该命令以重新准备暂存目录。仿真虚拟环境 `.venv` 独立保留，网站依赖不进入原有仿真依赖快照。

中文搜索在构建期使用 jieba 0.42.1 分词，少量电路术语保存在 `web/search_terms.txt`；浏览器仍只读取静态搜索索引。添加这项依赖是为了让“失调”“共模”等词能从连续中文句子中被查到，避免只能匹配整段文字开头。

MathJax 3.2.2 的 CHTML 组件和字体随站点提供，不从 CDN 加载公式资源。版本、包完整性与逐文件哈希在 `web/assets/vendor/mathjax/source.json`，Apache-2.0 许可证一并保存；需要恢复文件时执行 `python scripts/fetch_mathjax.py`。字体使用浏览器本地系统字体栈，无外部字体服务。

## 发布到 GitHub Pages

```powershell
.\.venv-site\Scripts\python.exe scripts/book.py deploy
```

该命令先从原始正文准备文件，再严格构建并用 MkDocs 的 `gh-deploy` 更新 `gh-pages`。没有使用 `--force`；`main` 保留教材源文件与正常修改历史。GitHub Pages 的发布来源配置为 `gh-pages` 的根目录。初次启用需要仓库管理权限，后续以 GitHub Pages 构建状态与实际访问检查为准。

网站发布和源文件提交是两件事：先审阅并提交正文，再部署，使网页记录对应的源提交可追溯。`gh-pages` 存放生成内容，不手工在那里修改教材。发布后检查首页、样章、公式、图片、导航、折叠附录、搜索和移动布局。

## 新增章节

在 `模拟/` 写普通 Markdown，并在 `scripts/book.py` 的 ROUTES 中指定稳定网址；同步更新 `mkdocs.yml` 的导航。原始链接仍指向仓库中的真实文件，由构建过程转换。图放在 `模拟/图/`，图注紧跟图片；图注以“图 ”开头，构建器才会把它组合成 figure。

检查 [知识覆盖](知识覆盖.md) 的状态，把未完成内容与已完成正文区分开。已有真实实验和模型继续按原有 [Windows 复现流程](WINDOWS.md) 维护，不能因重排阅读路径而移除。
