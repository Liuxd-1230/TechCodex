# 阅读站的构建与维护

在线地址：[TechCodex 阅读站](https://liuxd-1230.github.io/TechCodex/)。

## 单一正文来源

正文保存在仓库的 `模拟/`，在 GitHub 可以直接读。网站使用 MkDocs 1.6.1、Material 9.7.7；构建脚本把同一批文件复制到忽略的 `build/book-source/`，按稳定英文网址重写相对链接，然后构建 `site/`。不维护两份独立教材。

网站专用样式与模板在 `web/`。构建时的 figure/figcaption 转换只增强语义，不要求正文采用专用短代码。普通 Markdown、LaTeX 和原生 details 在 GitHub 仍可读。

发布范围由 `scripts/book.py` 的 `ROUTES` 指定：保留阅读页面、实验说明、页面实际引用的 SVG/PNG，以及 `web/assets/` 中的站点运行资源。原始 CSV、网表、工艺模型和开发脚本留在 GitHub 源仓库，正文中的相对链接在构建时转换为对应源文件或目录链接。新增图片使用普通 Markdown 图片语法，构建器据此收集资源。

历史验收和维护页面保留原网址，通过 MkDocs 的 `not_in_nav` 隐藏于主要导航，并用页面的 `search.exclude` 排除搜索；知识覆盖、资料来源和实验入口继续可查。不要删除旧路由来整理导航。

```powershell
uv sync --locked --group site
uv run --locked --group site scripts/book.py build
uv run --locked --group site scripts/check_site.py
uv run --locked --group site scripts/book.py serve
```

`build` 使用严格模式。`serve` 默认监听 `127.0.0.1:8000`，不向局域网公开；源文件修改后重启该命令以重新准备暂存目录。所有依赖使用同一 `uv.lock`；网站构建工具属于 `site` dependency group，默认仿真环境不会安装它们。

中文搜索在构建期使用 jieba 0.42.1 分词，少量电路术语保存在 `web/search_terms.txt`；浏览器仍只读取静态搜索索引。添加这项依赖是为了让“失调”“共模”等词能从连续中文句子中被查到，避免只能匹配整段文字开头。

MathJax 3.2.2 的 CHTML 组件和字体随站点提供，仅在正文含公式标记时由模板载入，不从 CDN 加载公式资源。版本、包完整性与逐文件哈希在 `web/assets/vendor/mathjax/source.json`，Apache-2.0 许可证一并保存；需要恢复文件时执行 `python scripts/fetch_mathjax.py`。字体使用浏览器本地系统字体栈，无外部字体服务。

## 发布到 GitHub Pages

```powershell
uv run --locked --group site scripts/book.py deploy
```

该命令先从原始正文准备文件，再严格构建并用 MkDocs 的 `gh-deploy` 更新 `gh-pages`。没有使用 `--force`；`main` 保留教材源文件与正常修改历史。GitHub Pages 的发布来源配置为 `gh-pages` 的根目录。初次启用需要仓库管理权限。

网站发布和源文件提交是两件事：先在本地检查首页、修改章节、公式、图片、导航、折叠附录、搜索和移动布局，再审阅并提交正文，最后部署，使网页记录对应的源提交可追溯。`gh-pages` 存放生成内容，不手工在那里修改教材。

## 电路交互样板

第 6 章 [米勒交互](../模拟/06-频率响应/02-米勒与共源.md) 通过 `<!-- interactive: miller-poles -->` 引入 `web/demos/miller-poles.html`、`miller-poles.js` 与纯计算模块 `frequency-model.mjs`。电路编辑源为 `web/demos/miller-schematic.svg`，构建时直接内联。只提供 Cgd 与观察频率两个滑块，低频固定增益近似主动勾选；幅度/相位坐标固定，观察频率为对数刻度。原理图内显示归一化节点相量，跨端压差和电流由同一个双节点解计算；蓝色箭头定义电流正方向。数值模型通过独立 KCL 与显式线性原生 SPICE 核验；无脚本仍有完整静态图与推导。`node scripts/check_frequency_demo.mjs` 检查控制范围。第 6 章实际 GF180 数据留在独立实验目录，不混入解析控件。

第一个样板放在 [4.1 电流如何分配](../模拟/04-差分放大器/01-电流如何分配.md)，只在推导前加入一段“预测 → 操作 → 观察 → 理解”。正文仍有原来的电路图、真实工艺曲线和完整推导；交互不能成为理解文章的前置条件。

原始 Markdown 中的 `<!-- interactive: differential-steering -->` 由 `web/hooks.py` 在网页构建时替换成 `web/demos/current-steering.html`。HTML 提供原生 range、radio、details 和带标题/说明的内联 SVG；`web/assets/demos/current-steering.js` 管理联动，`steering-model.mjs` 只做数值计算，`circuit-demo.css` 负责局部样式。不增加前端框架、第三方图表库或运行中的后端。模块只在选用样板的章节载入，公共 CSS 很小。

SVG 电路与曲线共用工作点，颜色对应左右支路，电流箭头只改变粗细、不改变常规电流方向。移动端改为上下排布；滑块自带键盘支持，并补充含单位的 `aria-valuetext`，动态说明轻度延迟播报，数值和 SVG 说明实时更新。没有自动播放或循环动画。原生控件的可访问性依据可参见 [MDN slider 文档](https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Roles/slider_role)。

组件最初隐藏，只有模块和数据均加载成功才显示；加载失败给出静态阅读提示，禁用脚本时正文与两幅原图仍在。打印只使用正文和静态图。GitHub 阅读不会出现一组无法工作的控件。

### 解析与工艺数据的边界

解析模型使用固定 β、固定阈值、饱和区平方律，分段处理单管截止；参数只按标称 GF180 端口斜率与尾电压对齐，不能当作提取的工艺参数。尾电流可在 40–100 µA 调节，整个滑块范围已检查饱和余量。图的纵轴保持不变，避免自动缩放掩盖电流总量变化。

GF180 模式只使用原有 `ideal-steering-sweep.csv` 的 651 个固定条件点，滑块中间值逐列线性插值，不外推，也不缩放到其他尾电流。此模式锁定 80 µA；切回解析模式恢复先前的解析偏置。默认只画当前模型两条曲线，主动勾选对照且同为 80 µA 时才叠加。观察视角由读者明确切换：完整转向为 ±650 mV、0–100 µA，零点附近为 ±40 mV、15–65 µA，二者均固定坐标；切到局部视图时，超出范围的当前输入收回到边界。微小漏流切换到 nA 显示，完整体端相关电流未被归一化消除。

`scripts/export_steering_demo.py` 从已有 CSV 和 metrics 打包 JSON；校验原仿真记录的源哈希，保留模型提交、仿真版本、条件、执行时间和输入文件哈希。JSON 使用 LF，保证 Windows 提交后的哈希稳定。重跑仿真后须重新导出：

```powershell
uv run --locked scripts/run_differential.py --check
python scripts/export_steering_demo.py
python scripts/export_steering_demo.py --check
node scripts/check_steering_demo.mjs
uv run --locked --group site scripts/book.py build
uv run --locked --group site scripts/check_site.py
```

Node 只用于开发期数值核验，网站部署和读者阅读不需要安装 Node。`check_steering_demo.mjs` 用独立的隐式 KCL 解检查解析结果、截止连续性、尾节点二次移动、输入换边和饱和余量，并核验工艺采样点、插值与禁止外推。站点检查同时检查控件标签、SVG 说明、静态回退和打包数据的新鲜度。

### 样板验证记录（2026-10-22）

本地严格构建与站点链接、图片、公式资产检查通过。原生 ngspice 的第 4 章 6 个网表已重跑，CSV 与 metrics 保持原数值，更新执行记录后重新导出网页数据。解析模型通过 1,827 个独立 KCL 工作点检查；GF180 的 651 个采样点和 650 个插值中点通过数据检查。

浏览器实际操作了拖动输入、键盘微调和 Home/End、输入归零、模型切换、尾电流调节及偏置恢复。在 1440×1000、390×844、320×780 视口检查布局与 SVG/公式加载，未出现整页横向溢出。禁用脚本时原图与推导保留，阻断 JSON 加载时显示阅读提示，打印时隐藏交互并保留静态图。正常交互未记录控制台错误；故意阻断数据的网络错误属于回退测试。窄视口检查不等于实体手机或各类读屏器兼容性认证。

### 按需复用

新增交互时先确定一个需要读者改变判断的问题，再决定最少的控件。复用这套分工与渐进增强方式：原始正文和静态图 → 构建钩子的显式标记 → 原生控件及 SVG → 独立模型或有来源的数据 → 数值与浏览器检查。不要把第 4 章的固定条件查表包装成通用 SPICE 求解器，也不要自动给每篇文章加面板。

第 5 章使用同样的显式标记加入 `mirror-compliance` 样板，静态原理图以内联 SVG 增强节点读数；只在所选章节载入模块。`scripts/export_mirror_demo.py` 校验原始两条工艺曲线哈希，`node scripts/check_mirror_demo.mjs` 检查原点、插值、边界以及“电流容差合格但上管未饱和”的反例。理论、工艺数据与实际运行 ngspice 的入口分开保留。

## 新增章节

在 `模拟/` 写普通 Markdown，并在 `scripts/book.py` 的 ROUTES 中指定稳定网址；同步更新 `mkdocs.yml` 的导航。原始链接仍指向仓库中的真实文件，由构建过程转换。图放在 `模拟/图/`，图注紧跟图片；图注以“图 ”开头，构建器才会把它组合成 figure。

检查 [知识覆盖](知识覆盖.md) 的状态，把未完成内容与已完成正文区分开。已有真实实验和模型继续按原有 [Windows 复现流程](WINDOWS.md) 维护，不能因重排阅读路径而移除。


## 第7章交互与全站阅读系统

噪声采用显式标记 `<!-- interactive: noise-band -->`，仅在带宽积分文章加载模块。`build_noise_demo.py`先核验实验记录，使用标准库导出固定工艺PSD；`noise-model.mjs`只负责谱插值和方差积分，DOM/动画在`noise-band.js`。优先修改教学问题，再决定是否复用，不自动给每页添加面板。

全站的纸面、页边、章节位置、目录和阅读进度在`web/assets/book.css`、`book.js`与模板中统一。`web/hooks.py`把原图包装为可打开的语义figure，给全局CSS/JS加内容哈希；源Markdown仍用普通本地文件链接。`PRODUCT.md`、`DESIGN.md`及`.impeccable/`是开发规范，不在构建输入白名单内，不会出现在阅读站。

重跑噪声后使用实验页的完整命令顺序。科学图必须注明数据来源、单位和频带，不对原始CSV做平滑；新绘图脚本随PNG写入来源元数据。MathJax继续自托管，无外部字体或图表运行库依赖。

## 跨章节的图示与交互

新增章节先对照邻近章节的真实桌面、手机效果，再决定是否增加图。概念图负责解释结构或因果；电气原理图负责给出真实连接；数据图负责检验判断。三者不能相互冒充。优先复用现有电路、绘图工具和交互，新的做法只在能改善具体理解问题时回用于旧章。

第 2 章的耗尽/反型分层和第 3 章的源跟随器电路注释图使用 diagram-design。版本化样式在 `web/diagrams/techcodex.md`，项目标记 `.diagram-design` 指向 `techcodex`；使用 DESIGN.md 的白纸、墨蓝、青色和本地中文字体。安装目录中的默认样式不改动。新机器若要继续用 Skill 编辑，可先恢复个人配置：

```powershell
New-Item -ItemType Directory -Force "$env:USERPROFILE/.diagram-design/profiles"
Copy-Item web/diagrams/techcodex.md "$env:USERPROFILE/.diagram-design/profiles/techcodex.md"
uv run --locked scripts/draw_concepts.py --skill-dir "$env:USERPROFILE/.codex/skills/diagram-design"
```

复制前保留已有的同名个人配置。上述命令针对本机已安装的 Skill 路径，其他安装位置用 `--skill-dir` 指定。生成器先写 `web/diagrams/*.html` 编辑源，通过 Skill 的离线自检后，用其 `export_svg.py --system-fonts` 导出 `模拟/图/*.svg`；正常 MkDocs 构建只使用已提交 SVG，不需要安装此 Skill。概念层厚、场强和电荷间距不表示工艺参数；因果箭头不表示电气导线。

概念图采用 320 单位的窄幅画布和不小于 13 单位的中文标注，桌面最高放到 400px 宽；更窄屏幕只在图内横向查看。所有带图注的图都有可见的原图链接，源 Markdown 保留普通图片和图注。复杂的已有原理图、真实工艺曲线保留原有电气含义和科学配色，不用概念图替代。

交互统一使用原生选择框、滑块、可展开来源说明和可读的观察文字。保持“预测 → 操作 → 观察 → 理解”，即时计算、预计算插值与 SPICE 运行分别标明；不为风格统一添加无教学意义的动画。减少动态效果偏好必须仍可完成操作。新增或实质修改后检查桌面、390px 手机及必要的窄屏；同时看正文、图注、数值、键盘反馈和失效条件，不能只看首页或 CSS 是否相同。
